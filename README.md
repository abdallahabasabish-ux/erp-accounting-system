# نظام الأعمال المحاسبي المؤسسي — ERP مزدوج القيد

تسليم كامل لإعادة هيكلة نظام إدارة الأعمال (المبني كـ CRUD من المتصفح على Firebase)
إلى **نظام محاسبي مؤسسي بمبدأ القيد المزدوج** متوافق مع IFRS، بالعربية بالكامل،
بمبالغ صحيحة بالقروش (1 ج.م = 100 قرش) — لا float إطلاقاً.

## محتويات التسليم

| المسار | الوصف |
|---|---|
| `../وثيقة-المعمارية-ERP-مزدوج-القيد.pdf` | الوثيقة المعمارية (18 صفحة): تحليل النظام القديم بدليل ملف:سطر + خطة إعادة الهيكلة الست مراحل + المعمارية + تصميم قاعدة البيانات + خريطة الترحيل + النشر |
| `../وثيقة-المعمارية-ERP-مزدوج-القيد.html` | مصدر الوثيقة (قابل للتعديل وإعادة التوليد) |
| `server/` | **خادم المحاسبة الكامل**: محرك القيد المزدوج + شجرة الحسابات + كل الموديولات + REST API + 28/28 اختباراً + ملفات النشر |
| `admin-dashboard/` | **كود لوحة التحكم** (Next.js 16 + TypeScript + shadcn/ui، عربية RTL بـ 14 قسماً) |

## البدء السريع — الخادم

```bash
cd server
cp .env.example .env
npm install
npm test        # 28/28 اختباراً للمحرك المحاسبي
npm start       # وضع تجربة ببيانات جاهزة على http://localhost:4000
```

مستخدمو التجربة (كلمة المرور `demo1234`):
`admin@demo.eg` (مدير نظام) · `manager@demo.eg` (مدير مالي) · `accountant@demo.eg` (محاسب) ·
`employee@demo.eg` (موظف) · `client@demo.eg` (عميل).

## البدء السريع — لوحة التحكم

```bash
cd admin-dashboard
npm install        # أو bun install
npm run dev        # http://localhost:3000  (الخادم يجب أن يعمل على :4000)
```

اللوحة تتصل بالخادم عبر وسيط داخلي `/api/erp/*` — لا CORS ولا وصول مباشر لقاعدة البيانات.
في الإنتاج: `ERP_API_URL=<رابط خادم Render/Railway>`.

## الانتقال للإنتاج (Firestore حقيقي)

1. أنشئ مفتاح خدمة: Firebase → Project Settings → Service Accounts → Generate new private key.
2. شغّل الخادم بـ `MODE=production` و`FIREBASE_PROJECT_ID` و`FIREBASE_SERVICE_ACCOUNT_JSON` (سطر واحد).
3. قدّم القواعد الصارمة والفهارس: `firebase deploy --only firestore:rules --only firestore:indexes`.
4. انشر الخادم على Render (ملف `server/render.yaml` جاهز) واللوحة على Vercel/Render.
5. التفاصيل الكاملة: `server/README.md` + القسم الحادي عشر من الوثيقة المعمارية.

## الضمانات المُثبتة بالاختبارات (28/28)

- كل قيد متوازن (∑ مدين = ∑ دائن) — والقيد غير المتوازن مستحيل بنيوياً.
- لا تعديل ولا حذف للقيود المرحّلة — التصحيح بقيد عكسي مرتبط (ومنع العكس المزدوج حتى بالتزامن).
- الفاتورة + قيدها + سند التحصيل + ذمم العميل + التدقيق في **معاملة واحدة** (Rollback كامل عند أي فشل).
- منع السحب المكشوف، الحد الائتماني، سقف السلفة، وقفل الفترات المغلقة — كلها داخل المعاملة.
- الترقيم الذري من الخادم: `INV/JE/REC/VCH-YYYY-######` بلا تكرار أو فجوات.
- ميزان المراجعة متوازن والمعادلة المحاسبية تحقق صفر فرق بعد كل تدفق.
- قيد إقفال سنوي يصفّر الإيرادات والمصروفات إلى الأرباح المبقاة ويقفل فترات السنة.
